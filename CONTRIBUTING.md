# Contributing

Contributions are welcome.

## Principles

Changes should preserve the project's goals:

- tool/vendor independence;
- proportional process instead of documentation bureaucracy;
- explicit separation of Spec (WHAT) and Design (HOW);
- verifiable claims about tests and QA;
- project facts kept out of global rules;
- safe defaults for Git and production-impacting actions.

For meaningful changes, open an issue or pull request explaining the problem and the proposed behavior. Adapter-specific changes should not leak vendor-specific assumptions into `core/`.
