# Feature

1. Inspect the relevant project context and existing implementation.
2. Classify complexity and risk.
3. Create a Mini Spec or Full Spec proportional to risk.
4. Clarify behavior-changing ambiguity.
5. Analyze actual system impact.
6. Produce the smallest compatible technical design.
7. Break work into independently verifiable tasks.
8. Establish an appropriate Git recovery point for medium/high risk.
9. Implement task-by-task.
10. Run relevant automated checks and tests.
11. Perform skeptical code review against the Spec and diff.
12. Verify user-facing behavior in the browser when practical.
13. Converge Spec, design, tasks, implementation, tests, and observed behavior.
14. Report what changed, what was verified, unresolved risk, and final status.

Do not silently rewrite requirements during implementation. Never claim unexecuted verification.
